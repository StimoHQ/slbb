## Твои рабочие принципы и лучшие практики
*   **NestJS:** Всегда разделяй ответственность: Controller -> Service. Используй DTO для валидации на входе и интерфейсы/типы для ответов.
*   **Структура модуля:** В корне `src/modules/<module>/` остаются только `*.service.ts`, `*.module.ts`, `*.controller.ts`. Всё вспомогательное уходит в подпапки: константы, хелперы и парсеры — в `utils/`, DTO — в `dto/`, контракты и переиспользуемые типы — в `interfaces/`. Barrel `utils/index.ts` заводим только тогда, когда модуль начинают читать из других модулей.
*   **Тесты:** `*.spec.ts` не лежат рядом с исходником — всегда `src/modules/<module>/test/`, а путь внутри `test/` зеркалит подструктуру модуля (`utils/gutenberg-txt-header.ts` → `test/utils/gutenberg-txt-header.spec.ts`). `nest g` сгенерирует spec рядом с файлом — после генерации переноси вручную. Запуск: `pnpm exec jest` (скрипта `test` в package.json нет); сборке тесты не мешают — `tsconfig.build.json` исключает `**/*spec.ts`.
*   **Prisma:** Для сложных запросов используй `$queryRaw` или `$transaction`. Всегда обрабатывай ошибки Prisma (например, `P2002` для уникальных полей).
*   **Очереди:** Для долгих задач создавай очереди.
*   **Конфигурация:** Используй модуль `@nestjs/config`. Все переменные окружения должны быть типизированы.
*   Не запуская сервер приложения и контейнеры сам. Я сделаю это сам. Твоя задача только удостовериться, что билд собирается без ошибок.
*   Если для решения задачи не совсем понятно что делать, то лучше спрашивай меня и предлагай варианты, из которых мне надо будет выбрать.

# Описание проекта:
- **Название**: Simple Language Barrier Breaker.
- **Суть**: Платформа для изучения английского языка через чтение контента. Пользователь читает контент, добавляет незнакомые слова в личный словарь, а система организует их интервальное повторение с помощью автоматических напоминаний.
- **Стадия**: MVP. Основной источник книг — бесплатные тексты из Project Gutenberg.
- **Реализуемая часть проекта:** Backend
## Core Functionality (MVP)
1.  **Источник книг**: Интеграция с Project Gutenberg (https://www.gutenberg.org/) для поиска и загрузки текстов книг. Например 
   https://www.gutenberg.org/cache/epub/79501/pg79501.txt
2.  **Языки**: Английский для изучения, Русский как основной язык пользователя. Поэтому, прежде чем скачивать полный текст, необходимо удостовериться, что текст контента на английском языке.
3.  **Интервальное повторение**: Автоматическая система напоминаний, которая планирует показ слов для повторения на основе алгоритма интервального повторения (например, SM-2).
4.  **Уведомления**: Автоматические напоминания пользователю о необходимости повторить слова (механизм пока не определен. Можно посылать уведомления в логи сервера).

## Текущая Архитектура проекта NestJS
```
NestJS Application Structure:
├── src/modules/          # Feature modules (user, text, gutenberg_loader, prisma)
├── src/modules/<module>/ # Feature module: в корне только *.service.ts, *.module.ts, *.controller.ts
│   ├── dto/ interfaces/ utils/ # Всё остальное по подпапкам: константы и хелперы в utils/
│   └── test/             # Unit тесты: *.spec.ts, путь внутри зеркалит подструктуру модуля
├── src/common/           # Shared utilities, interfaces, helpers
├── src/interceptors/     # Global response transformation & timing interceptors
├── src/filtres/          # Global HTTP exception filter
└── src/main.ts           # Application entry point
```
В каждом модуле может быть также свои локальные интерфейсы, типы, для переиспользования в других сервисах.

## Текущая Схема базы данных
Находится в prisma/prisma.schema 

Core models:
- **User**: User accounts
- **Text**: Book/article metadata (title, language, source)
- **TextContent**: Large text content (separate table for performance)
- **LexicalUnit**: Extracted words/phrases
- **LexicalUnitOccurrence**: Contextual occurrences in texts
- **UserLexicalUnit**: User's study status, notes, and progress tracking

Вызывать nest cli и prisma cli через pnpm nest / pnpm prisma - так как они установлены локально в проекте
